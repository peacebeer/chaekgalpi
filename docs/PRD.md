# 책갈피 PRD (초안)

2026-10-11 초안 · 원본: claude.ai 문서 「책갈피 PRD (초안)」

## 개요

책갈피는 회원들이 소그룹을 만들어 같은 책을 함께 읽고, 읽은 지점마다 메모·질문·감상을 서로 교환하는 웹 서비스다. 책 본문은 서비스하지 않는다. 각자 구한 책(종이책·전자책·도서관 대출)을 읽고, 책갈피는 그 사이에서 "어디까지 읽었고 무엇을 생각했는지"만 연결한다.

**문제.** 독서모임은 일정 맞추기가 어렵고, 단톡방에서는 진도가 다른 사람끼리 스포일러가 생기며, 대화가 흩어져 남지 않는다. 같은 책이라도 판본·형식이 달라 "몇 쪽"으로는 위치를 맞출 수 없다.

**해법 한 줄.** 판본과 무관한 위치 체계(장·절·퍼센트) 위에 메모를 쌓고, 내가 그 지점까지 읽었을 때만 다른 사람의 메모가 열리는 비동기 교환 독서.

## 목표와 비목표

MVP의 목표는 한 그룹이 한 권을 끝까지 함께 읽게 만드는 것이다. 수치는 출시 후 첫 분기 기준의 가설이며, 베타에서 보정한다.

**목표**

- 그룹 완독률: 시작한 그룹의 40% 이상이 마지막 장까지 진도 기록
- 교환 밀도: 활성 회원 1인당 책 한 권에 메모 10개 이상
- 재참여: 첫 그룹을 마친 회원의 30% 이상이 다음 그룹에 참여
- 스포일러 신고: 메모 1,000개당 1건 미만

**비목표**

- 책 본문·전자책·PDF의 열람, 업로드, 공유, 판매
- 실시간 화상 독서모임 (외부 도구 링크로 대체)
- 대규모 공개 리뷰 커뮤니티 (그룹 단위의 닫힌 교환에 집중)

## 타깃 사용자

1차 타깃은 혼자 읽기는 작심삼일이지만 정기 모임에 나갈 시간은 없는 20–40대 직장인·대학원생이다.

| 페르소나 | 상황 | 책갈피에서 원하는 것 |
| --- | --- | --- |
| 지은 (32, 회사원) | 퇴근 후 전자책으로 30분씩 읽음, 모임 시간 맞추기 어려움 | 내 속도로 읽되 같이 읽는 느낌, 스포일러 없는 대화 |
| 민호 (27, 대학원생) | 도서관 대출 위주, 책을 사기 부담됨 | 도서관에서 빌릴 수 있는 책으로 그룹 찾기 |
| 수연 (41, 모임 운영자) | 오프라인 독서모임 운영 중, 단톡방 관리에 지침 | 진도 현황과 토론 질문을 한곳에서 관리 |

## 핵심 원칙: 본문 없이 같은 책 읽기

책갈피는 책의 메타데이터와 회원의 생각만 저장하고, 본문은 각자가 합법적으로 구한 책에서 읽는다. 이를 위해 세 가지 장치를 둔다.

**1. 책 구하기 경로 안내 (콘텐츠 대신 연결)**

| 경로 | 방식 | 서비스 역할 |
| --- | --- | --- |
| 각자 구매 | 종이책·전자책을 각자 구입 | 온라인 서점 링크, 판본별 가격 표시 |
| 도서관 대출 | 공공도서관 종이책·전자도서관 | 국립중앙도서관·도서관 정보나루 등 공개 API로 지역별 소장·대출 가능 여부 표시 |
| 오디오북 | 각자 구독 서비스 이용 | 형식 표시와 진도 환산만 지원 |

**2. 대표 도서 기준 위치.** 그룹 리더가 그룹을 만들 때 대표 도서 한 권을 정하고, 그 책의 목차가 그룹 전체의 위치 기준이 된다. 그룹원은 입장만 하면 되고, 어떤 판본·번역본을 읽든 상관없다. 위치는 대표 도서의 장 번호와 장 안의 진도(%)로 기록한다. 대표 도서와 같은 책을 읽는 회원은 쪽수로도 입력할 수 있다.

**3. 인용은 그룹당 한 번만.** 본문 인용은 그룹 안에서 하나의 "인용 카드"로 등록되고, 같은 문장에 대한 다른 회원의 감상은 그 카드에 덧붙는다. 같은 문장을 여러 사람이 다시 타이핑하지 않으므로 입력 수고와 그룹 내 인용 총량이 함께 줄어든다. 인용 카드 하나는 300자(약 5문장) 이하이고, 출처(책·장)를 자동 표기하며, 처음 등록할 때 본인 감상을 함께 써야 한다. 한 그룹이 한 책에 등록할 수 있는 인용 합계에도 상한(기본값 10,000자, 설정값으로 조정)을 둔다. 사진·스캔 이미지로 본문 페이지를 올리는 것은 금지한다.

## 핵심 사용자 여정

회원은 그룹에 들어가 각자 책을 구한 뒤, 읽고 진도를 기록하고 위치가 붙은 메모를 남긴다. 다른 그룹원은 자기 진도가 그 위치에 도달해야 메모를 볼 수 있다.

> 흐름: 그룹 만들기·참여 → 각자 책 구하기 → 읽고 진도 기록 → 위치 태그 붙은 메모 남기기 → (그룹원 진도가 그 위치 이상이면) 메모 공개, (아니면) 흐림 처리 후 진도가 따라잡으면 공개 → 마지막 장까지 반복 → 완독·정리 노트

흐림 처리된 메모는 진도가 따라잡는 순간 자동으로 열리므로, 빠른 사람과 느린 사람이 같은 그룹에서 스포일러 없이 교환할 수 있다.

## 기능 요구사항

MVP는 그룹 만들기, 진도 기록, 진도 잠금 메모 세 가지가 동작하면 출시할 수 있다.

| 영역 | 기능 | 단계 |
| --- | --- | --- |
| 계정 | 이메일·슬글 로그인(카카오는 MVP 이후 검토), 프로필, 읽고 싶은 책 목록 | MVP |
| 책 | 그룹 리더가 대표 도서 1권 설정: 국립중앙도서관 API로 제목·저자·ISBN 검색과 목차(장 구조) 불러오기 | MVP |
| 책 | API에서 책 정보나 목차를 불러오지 못하면 리더가 직접 입력·수정. 장 시작 쪽은 선택 입력 | MVP |
| 그룹 | 그룹 생성(책, 정원 3–8명, 시작일, 목표 완독일), 초대 링크, 공개 모집 | MVP |
| 그룹 | 주차별 읽기 범위(예: 1주차 1–3장) 설정 | MVP |
| 진도 | 대표 도서 목차 기준으로 장 선택 + 장 안 위치 슬라이더. 대표 도서와 같은 책이고 장 시작 쪽이 입력돼 있으면 쪽수로도 입력. 그룹 진도 현황판 | MVP |
| 교환 | 인용 카드 등록: 위치 태그 + 본문 인용(300자 이하) + 본인 감상, 출처 자동 표기 | MVP |
| 교환 | 인용 공유 감상: 그룹원이 이미 등록된 인용 카드에 자기 감상을 추가, 카드 아래 감상이 모여 보임 | MVP |
| 교환 | 중복 인용 안내: 인용을 입력하는 중 같은 장의 비슷한 기존 카드를 자동 제안하고 "여기에 감상 남기기"로 연결 (다른 문장이면 새로 등록 가능) | MVP |
| 교환 | 위치만 붙인 메모·질문 (인용 없이) | MVP |
| 교환 | 진도 잠금: 내 진도보다 뒤 위치의 인용 카드·메모는 흐림 처리, 도달하면 공개 | MVP |
| 교환 | 반응: 그룹원의 감상·메모에 좋아요를 남기고, 좋아요 수와 누른 사람 표시 (반응은 좋아요 한 종류) | MVP |
| 교환 | 감상·메모에 답글, 장 끝 "정리 노트" | MVP |
| 알림 | 내 인용 카드에 새 감상, 내 감상에 반응·답글, 주차 마감 리마인드 (이메일·웹 푸시) | MVP |
| 구하기 | 서점 링크, 도서관 소장 조회 | MVP |
| 교환 | 교환 일기 모드: 정해진 순서로 한 사람씩 장 단위 노트를 이어 씀 | 2단계 |
| 운영 | 운영자용 토론 질문 템플릿, 모임 일정 링크 | 2단계 |
| 기록 | 완독 후 그룹 독서 기록 내보내기(PDF·이미지, 회원 감상 중심) | 3단계 |
| 추천 | 읽은 책·감상 기반 다음 책·그룹 추천 | 3단계 |

## 정책

저작권과 회원 간 신뢰가 서비스의 존립 조건이므로, 아래 정책을 약관과 제품 동작 양쪽에 반영한다.

- **저작권:** 본문 파일(PDF, EPUB 등)·페이지 사진 업로드 차단. 인용 카드당 300자 이하, 출처 자동 표기, 첫 등록 시 감상 필수, 같은 문장은 그룹당 한 카드, 그룹·책당 인용 합계 10,000자 이하. 권리자 신고 창구와 게시 중단 절차 운영.
- **스포일러:** 진도 잠금을 기본값으로 두고, 위치 태그 없는 메모는 "책 전체" 위치로 간주해 완독자에게만 공개.
- **커뮤니티:** 그룹 운영자의 강퇴·감상 숨김 권한, 회원 신고, 반복 위반 시 이용 제한.
- **인용 카드 소유:** 다른 회원의 감상이 하나라도 달리면 카드는 잠기고, 최초 등록자는 오타 수정만 할 수 있다. 등록자가 탈퇴해도 카드와 감상은 남는다.
- **개인정보:** 최소 수집(이메일, 닉네임). 감상·반응의 공개 범위는 그룹 내부가 기본.

## 데이터 모델과 비기능 요구사항

핵심은 그룹마다 대표 도서 한 권을 두고, 모든 인용 카드와 감상이 대표 도서 목차 기준 위치(장, %)를 가리키게 하는 것이다.

| 엔티티 | 주요 필드 |
| --- | --- |
| User | id, 닉네임, 이메일, 지역(도서관 조회용) |
| Book (대표 도서) | id, ISBN, 제목, 저자, 역자, 출판사, 출처(국립중앙도서관·직접 입력) |
| BookChapter | book\_id, 장 번호, 장 제목, 시작 쪽(선택) |
| Group | id, book\_id, 리더, 정원(최대 8), 시작일, 목표 완독일, 공개 여부 |
| Membership | group\_id, user\_id, 역할, 진도(장, %), 완독 여부 |
| Quote (인용 카드) | id, group\_id, 위치(장, %), 인용문(300자 이하), 최초 등록자, 잠금 여부 |
| Note (감상·메모) | id, group\_id, 작성자, 위치, quote\_id(인용 카드에 단 감상이면), 유형, 본문(필수), 상위 note\_id(답글이면) |
| Reaction | note\_id, user\_id, 시각 (좋아요 한 종류, note·user 조합은 하나만) |

**비기능 요구사항**

- 모바일 웹 우선 반응형 (책을 읽다 휴대폰으로 메모하는 사용 패턴)
- 진도 잠금 판정은 서버에서 수행해 API 응답에 잠긴 메모 본문을 포함하지 않음
- 메모 작성 후 그룹원 화면 반영 5초 이내
- 메모 본문 외 책 본문 데이터는 저장하지 않음

## 로드맵, 리스크, 열린 질문

1. **MVP 구현:** 그룹, 진도, 진도 잠금 메모, 구하기 링크. 지인 몇 명과 실제로 한 권을 읽어 보며 유용성 검증.
2. **배포 실습:** 실제 출시 전 단계를 미리 연습한다.
   - 도메인 연결과 HTTPS
   - 프런트·백엔드·DB 호스팅 구성과 환경 변수(비밀 키) 관리
   - GitHub 기반 CI/CD: 테스트 통과 시 자동 배포, 스테이징과 운영 분리
   - 에러 추적(Sentry 등)·요청 제한·DB 백업 — 도구는 이 단계에서 결정
   - 이용약관·개인정보처리방침 초안, 구글 로그인 앱 검수 절차
3. **2단계:** 교환 일기 모드, 운영자 도구.
4. **3단계:** 독서 기록 내보내기, 추천, 공개 모집 확대. 실제 배포를 결정하면 이때 법률 검토와 수익 모델을 다룬다.

**리스크**

| 리스크 | 대응 |
| --- | --- |
| 목차 데이터가 없어 위치 체계가 작동하지 않음 | 회원 입력 목차 + 퍼센트만으로도 동작하도록 설계 |
| 판본 간 장 구성이 다름(번역본, 개정판) | 대표 도서 목차를 기준으로 삼고, 다른 판본·번역본 독자는 가장 가까운 장과 대략 위치로 입력. 위치가 근사치임을 화면에 안내 |
| 메모 인용이 사실상 본문 공유로 변질 | 인용 300자 제한, 본인 글 필수, 연속 인용 탐지, 신고·게시 중단 절차 |
| 그룹 중도 이탈로 교환이 끊김 | 주차 리마인드, 진도 비슷한 회원끼리 메모 우선 노출 |

## 기술 스택 제안

**조사 중 확인한 주의점**

- 국립중앙도서관 [ISBN 서지정보 API](https://www.nl.go.kr/NL/contents/N31101030500.do)는 목차 필드를 제공하지만, 목차 파일 URL은 2021년 2월까지 생성된 데이터만 있다. 최근 책은 목차가 비어 있을 가능성이 높아 "회원 직접 입력"이 사실상 주 경로가 될 수 있다. 구현 첫 주에 실제 책 20권 정도로 목차 채움 비율을 확인하길 권한다.
- API 호출에는 인증키가 필요하므로 브라우저에서 직접 부르지 말고 서버(라우트 핸들러)를 거쳐야 한다.

## DB 설계

모든 인용 카드와 감상은 판본이 아니라 "그룹 + 위치(장 번호, 장 내 %)"를 가리키고, 진도 잠금은 이 위치를 회원의 진도와 비교해 DB에서 판정한다. 아래는 구현 전 검토용 설계이며, 실제 SQL은 구현 단계에서 마이그레이션 파일로 작성한다.

> 관계: book_chapters → books ← groups ← memberships / notes → groups, notes → quotes, reactions → notes. 작성자·회원 컬럼은 모두 profiles를 가리킨다.

감상(notes)과 인용 카드(quotes)의 위치가 memberships에 저장된 내 진도 이하일 때만 조회된다. 위치는 그룹 리더가 정한 대표 도서의 목차를 기준으로 한다.

### 테이블

| 테이블 | 주요 컬럼 | 비고 |
| --- | --- | --- |
| profiles | id(= 인증 사용자 id), nickname, region, created\_at | 회원 가입 시 자동 생성 |
| books | id, isbn, title, author, translator, publisher, source(nlk·manual), created\_by | 대표 도서. 같은 ISBN이면 여러 그룹이 재사용 |
| book\_chapters | book\_id, number, title, start\_page | (book\_id, number) 고유. start\_page는 선택 |
| groups | id, book\_id, owner\_id, name, capacity(3–8), start\_date, target\_date, is\_public, invite\_code(고유), quote\_limit(기본 10,000) | owner가 그룹 리더 |
| memberships | group\_id, user\_id, role(owner·member), progress\_chapter, progress\_pct, finished\_at | (group\_id, user\_id) 고유 |
| quotes | id, group\_id, chapter, pct, text(1–300자), created\_by, locked\_at, created\_at | 인용 카드 |
| notes | id, group\_id, author\_id, chapter, pct, kind(감상·메모·질문·정리), body(필수), quote\_id, parent\_id, created\_at | quote\_id가 있으면 인용 카드에 단 감상, parent\_id가 있으면 답글 |
| reactions | note\_id, user\_id, created\_at | (note\_id, user\_id) 고유 = 좋아요 한 번만 |

**위치 표기.** 위치는 (chapter, pct) 한 쌍이다. PostgreSQL은 `(chapter, pct) <= (2, 40)`처럼 쌍을 순서대로 비교할 수 있어 진도 비교가 한 줄로 끝난다. 위치 태그가 없는 메모는 chapter를 비워 두고 "책 전체"로 취급해 완독자(finished\_at 있음)에게만 보인다.

**진도 입력.** 기본은 대표 도서 목차에서 장을 고르고 슬라이더로 장 안 위치를 정하는 방식이다. 리더가 장 시작 쪽을 입력해 두었다면, 대표 도서와 같은 책을 읽는 회원은 "143쪽"처럼 쪽수로 입력할 수 있고 (3장, 40%)로 자동 환산된다. 다른 판본·번역본을 읽는 회원은 장과 대략 위치로 입력하며, 장 안의 위치는 근사치다.

**비슷한 인용 카드 추천.** 회원이 인용을 입력하면 같은 장에서 텍스트가 비슷하거나 위치가 가까운 기존 카드를 보여준다. 다른 번역본이라 문장이 달라도 위치로 찾을 수 있으므로, 회원은 기존 카드에 감상을 남기거나 새 카드를 등록할 수 있다.

### 진도 잠금 RLS 규칙

세 개의 도우미 함수를 두고 모든 정책이 이를 사용한다.

- `is_member(group)`: 지금 로그인한 사람이 그 그룹 회원인가
- `my_position(group)`: 그 그룹에서 내 진도 (chapter, pct)
- `can_see(group, chapter, pct)`: 회원이고, 위치가 내 진도 이하이거나 내가 완독했는가

| 테이블 | 조회 | 작성 | 수정 | 삭제 |
| --- | --- | --- | --- | --- |
| profiles | 본인, 같은 그룹 회원 | 가입 시 자동 | 본인 | 탈퇴 시 |
| books·book\_chapters | 로그인한 모두 | 로그인한 모두(직접 입력용) | 등록자, 아무도 감상하지 않은 장만 | 불가 |
| groups | 공개 그룹 또는 회원 | 로그인한 모두(owner = 본인) | 운영자 | 운영자 |
| memberships | 같은 그룹 회원 | 함수 `join_group(초대코드)`로만 | 본인 진도만 | 본인 탈퇴, 운영자 강퇴 |
| quotes | `can_see` 통과 | 함수 `create_quote(…)`로만 | 등록자, 잠금 규칙 적용 | 등록자, 잠기기 전만 |
| notes | `can_see` 통과 | 본인, `can_see` 통과 위치에만 | 작성자 | 작성자, 운영자 숨김 |
| reactions | 감상을 볼 수 있으면 | 본인, 볼 수 있는 감상에만 | 불가 | 본인 |

**흐림 처리 표시.** 잠긴 카드·감상은 RLS 때문에 아예 조회되지 않는다. 화면에 "3장에 잠긴 감상 4개"처럼 흐린 자리를 보여주기 위해, 본문 없이 장별 개수만 돌려주는 함수 `locked_counts(group)`를 따로 둔다.

**실시간.** Supabase Realtime의 DB 변경 알림도 RLS를 따르므로, 아직 도달하지 않은 위치의 감상은 실시간으로도 전달되지 않는다.

### 제약 조건과 트리거

| 규칙 | 구현 방법 |
| --- | --- |
| 인용문 1–300자, 감상 본문 필수 | 컬럼 CHECK 제약 + Zod |
| 인용 카드 등록 시 감상 필수 | `create_quote(위치, 인용문, 감상)` 함수가 카드와 첫 감상을 한 트랜잭션으로 저장. quotes에 직접 INSERT는 막음 |
| 그룹·책당 인용 합계 10,000자 | `create_quote` 안에서 기존 합계 + 새 인용 길이를 groups.quote\_limit과 비교 |
| 같은 장의 비슷한 카드 제안 | 같은 장 카드 중 텍스트 유사도가 높거나(PostgreSQL 유사도 확장 pg\_trgm) 위치가 가까운(±5%) 카드를 돌려주는 함수 |
| 다른 회원 감상이 달리면 카드 잠금 | notes INSERT 트리거: 작성자가 카드 등록자가 아니면 quotes.locked\_at 기록 |
| 잠긴 카드는 오타 수정만 | quotes UPDATE 트리거: 잠긴 뒤에는 변경 글자 수가 작을 때만 허용(기준값은 열린 질문) |
| 감상 위치 = 카드 위치 | notes INSERT 트리거가 quote\_id의 위치를 그대로 복사 |
| 그룹 정원 8명 | `join_group` 함수에서 현재 인원 확인 |
| 등록자 탈퇴 후 카드 유지 | created\_by를 탈퇴 시 비우도록(ON DELETE SET NULL) 설정 |

### pgTAP 테스트 목록 (CI에서 실행)

- [ ] 1장 20%까지 읽은 회원은 2장 카드·감상을 조회할 수 없다
- [ ] 그룹 밖 회원은 그 그룹의 어떤 카드·감상도 조회할 수 없다
- [ ] 자기 진도보다 뒤 위치에는 감상을 쓸 수 없다
- [ ] 다른 회원 감상이 달린 카드는 등록자도 삭제할 수 없다
- [ ] 남의 감상은 수정·삭제할 수 없다
- [ ] 같은 감상에 같은 사람이 좋아요를 두 번 누를 수 없다
- [ ] 인용 합계가 10,000자를 넘는 카드는 등록되지 않는다
- [ ] 쪽수가 장 시작 쪽 기준으로 (장, %)로 올바르게 환산된다
- [ ] RLS가 꺼진 테이블이 하나도 없다
